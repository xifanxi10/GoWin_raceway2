## 2. 系统分工和实现边界

F429 负责：

1. 定时采集八路压力传感器的 ADC 原始读数。
2. 将完整的八路快照打包，通过压力串口发送给 FPGA。
3. 驱动 RGB 显示，读取电容触摸坐标，处理界面操作。
4. 将界面设置转换为控制指令，管理 FPGA 回复、超时及重试。
5. 保存本次运行的期望配置与已确认配置，维护错误计数。

FPGA 负责：

1. 压力校准、必要数字滤波、按下／松开识别、力度映射。
2. 音符映射、声部分配、相位累加、波形生成、ADSR、混音。
3. 逐样本产生音频并通过 I2S 输出到 DAC。

**第一版 F429 只传原始压力测量值，不计算音频波形，不播放乐器录音，不代替 FPGA 生成 ADSR 音频包络。**

赛题背景：基础要求至少两个独立演奏控制维度、至少 4 复音、演奏总延迟不超过 10 ms；拓展包含至少 32 复音、至少两种音色等。八个压力键可用“键位选择音高 + 压力控制力度”构成两个控制维度。32 复音由 FPGA 内部独立声部能力实现，与把八键整体升降八度无关。

根据用户提供的赛题文字，MCU 辅助采集和设置不属于音频合成；不要将这一工程解释表述为官方已批准辅助 MCU。

## 4. 推荐外设与时钟配置

### 4.1 总体配置

| 功能 | 建议外设 | 参数 |
|---|---|---|
| 八路采集 | ADC1 | 规则组扫描 8 路，12 位，右对齐 |
| 采集节拍 | TIM2 TRGO | 每 1 ms 触发一轮八路扫描 |
| 采集搬运 | ADC DMA | Circular，16 个 uint16 元素，两个八路半区 |
| 压力链路 A | USART3 TX | 1,000,000 bps，8N1，发送 DMA |
| 控制链路 B | USART1 TX/RX | 115,200 bps，8N1，双向 |
| RGB 显示 | LTDC | 按屏幕资料；DMA2D 可辅助绘制 |
| 电容触摸 | 通常为 I²C + INT + RST | 按触摸芯片资料 |
| 帧缓冲 | 常见为 FMC 外部 SDRAM | 按分辨率、像素格式和缓冲数量计算 |

USART3 和 USART1 是建议编号，不是必须编号。不得因编号固定而与板上 LTDC、FMC、ADC 或其他外设引脚冲突。

### 4.2 ADC 设置

| CubeMX 配置项 | 建议值 |
|---|---|
| ADC Mode | Independent |
| Resolution / Data Alignment | 12 bit / Right |
| Scan Conversion Mode | Enable |
| Number of Conversions | 8 |
| Continuous Conversion Mode | Disable |
| Discontinuous Conversion Mode | Disable |
| External Trigger Source | TIM2 TRGO |
| External Trigger Edge | Rising |
| EOC Selection | End of sequence |
| DMA Continuous Requests | Enable |
| ADC DMA Mode / Direction | Circular / Peripheral to memory |
| DMA Peripheral / Memory Width | Half Word / Half Word |
| Peripheral / Memory Increment | Disable / Enable |
| ADC GPIO | Analog / No pull |
| Sampling Time | 先按 144 Cycles 评估，结合源阻抗验证 |

注意：ADC 连续转换关闭，DMA 连续请求开启。每次定时器触发完成整个八路序列，随后等待下一次触发。

Rank 1～8 固定对应压力键 1～8；实际 ADC 通道号可以不连续。最终交付中必须有“压力键编号—引脚—ADC 通道—Rank”的对应表。

### 4.3 采样率、采样时间和音频采样率

- 每路压力采样率为 1 kHz，总转换量为 8000 次/秒。
- 每 1 ms 得到一组完整八路数据，发送一帧。
- ADC 的 Sampling Time 是采样电容获取电压的周期数，不是每秒采样次数。
- FPGA 音频输出暂按 48 kHz，两者不要求同频，也不要求使用同一时钟。

时钟示例：PCLK2 = 90 MHz，ADC 分频 /4，得到 ADCCLK = 22.5 MHz。12 位 ADC 单次转换时间约为 `(SamplingCycles + 12) / ADCCLK`。

- 144 Cycles：八路转换约 55.5 μs。
- 480 Cycles：八路转换约 174.9 μs。

上述示例不是固定系统时钟要求。高阻输入可能需要更长采样时间或模拟缓冲，应根据电路验证精度。ADC 输入不得超出器件允许范围。

### 4.4 TIM2

使用内部时钟、向上计数，TRGO 选择 Update Event。

`触发频率 = TIM2CLK / [(PSC + 1) × (ARR + 1)]`

- TIM2CLK = 90 MHz：PSC = 89，ARR = 999。
- TIM2CLK = 84 MHz：PSC = 83，ARR = 999。

以实际时钟树为准，考虑 APB 分频和 TIMPRE，不能直接把 CPU 主频当成 TIM2CLK。先准备好 DMA 和 ADC 外部触发，再启动定时器。

### 4.5 DMA 映射示例

| 功能 | F429 可选映射示例 |
|---|---|
| ADC1 | DMA2 Stream0 / Channel0 |
| USART3 TX | DMA1 Stream3 / Channel4 |
| USART1 TX | DMA2 Stream7 / Channel4 |
| USART1 RX | DMA2 Stream2 / Channel4 |

使用 CubeMX 和 RM0090 核对全工程的 DMA 冲突。DMA 缓冲区放在 DMA 可访问的 SRAM，不放在 CCM RAM。控制接收可用循环 DMA + IDLE，也可在低数据量下使用简短接收中断；与项目 HAL 版本一致。

## 5. 压力采集到发送的运行约定

1. ADC DMA 缓冲区长度为 16 个 uint16，前八个和后八个分别代表一轮扫描。
2. 半传输完成时取前半区，全传输完成时取后半区，所以仍然每 1 ms 处理一帧。
3. 及时复制已完成半区的完整八路快照；约一个采样周期后该半区可能开始被复用。
4. 采集缓冲区与串口发送缓冲区分离。
5. 发送 DMA 正在读取的缓冲区不可修改；使用明确的缓冲区所有权和有界临界区处理并发。
6. 可设置一个正在发送的帧和一个待发送的最新帧。异常拥塞时替换尚未开始发送的旧压力帧并记录丢帧，不能无限排队。
7. 帧序号按采集轮次递增；发生发送丢帧后，接收端能看到序号跳变。
8. 中断中不绘制屏幕、不等待串口、不做阻塞延时。短快照复制等操作必须能在预算内完成。
9. 压力路径优先于界面。LCD、DMA2D 和 SDRAM 仍可能争用总线，要在界面持续刷新时测试。
10. 不使用主循环 `HAL_Delay(1)` 充当精确采样节拍，不累积几十轮数据才发送。

需要记录 ADC 溢出、DMA 错误、压力丢帧、控制超时和重试次数。调试信息不能混入两条协议串口。

## 6. 压力链路 A：22 字节固定帧

方向：F429 → FPGA。1 Mbps，8 数据位、无校验、1 停止位、无硬件流控。

| 字节位置 | 字节数 | 内容 |
|---|---:|---|
| 0～1 | 2 | 帧头 `AA 55` |
| 2～3 | 2 | uint16 采集序号，小端，按模 65536 递增 |
| 4～19 | 16 | 压力键 1～8，每路 uint16，小端；数值 0～4095 |
| 20～21 | 2 | CRC16，小端；覆盖字节 2～19 |

第 k 路（k=1～8）低字节位置为 `4 + 2 × (k−1)`。12 位 ADC 读数的高四位填零。不发送文本、不发送浮点、不直接发送含有编译器填充的 C 结构体内存。

CRC 全文统一为 **CRC-16/CCITT-FALSE**：

- Polynomial：`0x1021`
- Initial value：`0xFFFF`
- RefIn / RefOut：false / false
- XorOut：`0x0000`
- 检查向量：ASCII 字节串 `123456789` → `0x29B1`

完整示例：序号 1，八路值 `[120, 1000, 20, 2048, 55, 3000, 18, 4095]`：

```text
AA 55 01 00 78 00 E8 03 14 00 00 08 37 00 B8 0B 12 00 FF 0F 98 04
```

带宽：`22 × 10 × 1000 = 220000 bit/s`。1 Mbps 下占用约 22%，每帧传输约 0.22 ms。115200 bps 不适合这条持续压力链路。

FPGA 不逐帧 ACK。它应校验完整帧后原子更新八路快照，坏帧丢弃并继续搜索。负载中可能出现帧头字节，不可在帧中途仅凭帧头出现就重启解析。

## 7. 控制链路 B：16 字节固定帧

方向：F429 ↔ FPGA。115200 bps，8N1，无硬件流控。

连接：MCU TX → FPGA CTRL_RX；FPGA CTRL_TX → MCU RX。与压力串口共地，并核对双方电平。这里是逻辑电平串口，不是直接连接 RS-232。

| 字节位置 | 字节数 | 内容 |
|---|---:|---|
| 0～1 | 2 | 帧头 `5A A5` |
| 2 | 1 | 协议版本 `01` |
| 3 | 1 | 命令码 |
| 4～5 | 2 | uint16 事务序号，小端 |
| 6 | 1 | 目标：0=全局，1～8=压力键 |
| 7 | 1 | 保留，必须为 0 |
| 8～13 | 6 | 参数 P0～P5 |
| 14～15 | 2 | CRC16，小端，覆盖字节 2～13 |

参数未用字节填 0；`SET_CHORD` 的空音符槽按后文填 `FF`。所有多字节整数为小端。解析器必须能处理 DMA 分段、多个连续帧、垃圾字节、CRC 错误以及含有帧头字节的负载。

### 7.1 请求指令

| 命令码 | 名称 | 目标 | P0～P5 定义 |
|---|---|---|---|
| `0x00` | PING | 0 | 全 0 |
| `0x01` | SET_TIMBRE | 0 | P0：0=风琴类，1=拨弦类；其余 0 |
| `0x02` | SET_MASTER_GAIN | 0 | P0～P1：uint16，0～1000；其余 0 |
| `0x03` | SET_TRANSPOSE | 0 | P0：int8，−24～+24 半音；其余 0 |
| `0x04` | SET_KEY_NOTE | 1～8 | P0：音符编号 0～127；其余 0 |
| `0x05` | SET_MODE | 0 | P0：0=单音，1=和弦；其余 0 |
| `0x06` | SET_CHORD | 1～8 | P0：音数 1～4；P1～P4：音符编号，未用槽填 FF；P5=0 |
| `0x07` | RELEASE_ALL | 0 | 全 0 |
| `0x08` | SET_MUTE | 0 | P0：0=解除静音，1=静音；其余 0 |
| `0x10` | SET_ADSR_PARAM | 0 | P0：0=A、1=D、2=S、3=R；P1～P2：uint16 值；P3～P5=0 |
| `0x20` | GET_STATUS | 0 | 全 0 |

约定：

- 总音量为线性增益 `value / 1000`；界面 0～100% 可换算为 0～1000。混音防溢出由 FPGA 处理。
- 移调发送绝对值，不发送“再加一次”。升八度是加 12 半音；−12 的 P0 为 `F4`。
- 音符用常见 MIDI 音高编号，但本文协议不是 MIDI 协议。A4=69=440 Hz。
- 默认八键：`[60,62,64,65,67,69,71,72]`，界面标为 C4～C5。
- 实际音符 = 基础键位或和弦音符 + 全局移调。验证全部有效映射；任一结果不在 0～127 内就拒绝整次配置，不静默截断。
- ADSR 的 A/D/R 范围 0～5000 ms，S 范围 0～1000。0 ms 必须明确定义为立即进入下一阶段。
- 音色、键位、移调、模式、和弦、ADSR 仅对之后新触发的音生效。切换音色载入该音色默认包络。
- 音量、静音可影响正在发声的声音；FPGA 平滑增益，建议约 5 ms 过渡。
- RELEASE_ALL 使活跃声部进入释音。仍按住的键要先松开再按下才重新触发。
- 静音期间仍维护声部和按键状态，避免解除静音时释放逻辑错乱。

### 7.2 ACK 与状态回复

普通请求回复命令码 `0x80`：

- 帧版本仍为 1，序号与目标沿用请求。
- P0 = 原请求命令码。
- P1 = 状态码。
- P2～P5 = 0。

| 状态码 | 含义 |
|---|---|
| 0 | 成功，参数已提交 |
| 1 | 协议版本不支持 |
| 2 | 命令不支持 |
| 3 | 目标错误 |
| 4 | 参数越界 |
| 5 | 保留字段或未用参数非法 |
| 6 | 暂时忙，未执行 |

CRC 错误的请求丢弃，不回复 ACK。对于“只作用于新音”的设置，更新新音配置就可确认成功，不等待演奏动作。

`GET_STATUS` 成功时回复命令码 `0x81`，不再额外发成功 ACK。序号与目标沿用请求：

- P0：音色编号。
- P1：模式。
- P2：int8 移调量。
- P3：静音状态。
- P4～P5：uint16 总音量。

GET_STATUS 错误时仍用普通 ACK 返回错误。这个状态回复不包含完整键位、和弦或 ADSR，不能宣称它能读回全部配置。

### 7.3 已校验的十六进制向量

序号 1，设置音色为 1：

```text
5A A5 01 01 01 00 00 00 01 00 00 00 00 00 20 75
```

对应成功 ACK：

```text
5A A5 01 80 01 00 00 00 01 00 00 00 00 00 C3 24
```

CRC 数值已用两种计算实现交叉验证。后续代码应通过这些向量验证字节顺序、覆盖范围与帧长。

## 8. 控制事务状态机要求

- 控制链路同一时间只允许一个未完成事务，不使用阻塞等待。
- 从 UART 最后一个字节真正发送完成开始计时，等待回复 20 ms。
- 超时最多重发 2 次，即总计最多发送 3 次；重试保持原序号和原内容。
- 收到明确的版本、命令、目标、范围等错误后，不盲目重试，显示失败并保留已确认设置。
- 收到暂时忙可延后重试，沿用原事务并受总尝试次数限制；退避时间作为可配置参数。
- 匹配合法回复的序号、目标及原命令码；GET_STATUS 匹配 0x81。丢弃不匹配或迟到回复。
- FPGA 缓存最近一个已完成请求及回复；完全相同的重试只重发回复，不重复执行。暂时忙不缓存为已完成。
- UI 同时保存“用户期望值”和“FPGA 已确认值”。正在处理时显示待应用，成功后再更新已确认值。
- 对滑条合并尚未发送的旧设置，保留最新值；不能修改已经发送且仍等待 ACK 的事务内容。
- 按钮指令队列必须有界，定义满队列行为，不允许静默丢弃关键操作。
- 低优先级 GET_STATUS 建议每秒一次，不抢占正在进行的用户设置事务。

初次连接、明确复位或重新连接后，先使 FPGA 静音，再顺序同步配置：移调清零 → 音色 → 键位／和弦 → 目标移调 → 模式／音量 → 可选自定义 ADSR。每条确认后再继续；检查输入正常后由用户解除静音。

不要把 PING 成功视为全部配置已同步。原协议不包含会话号或启动计数器，不要宣称能够无条件识别所有瞬时复位；如项目需要更强复位检测，应明确升级协议并同步两端，而不是偷偷添加字段。

## 9. 屏幕硬件与界面任务

普通 RGB 屏通常由 LTDC 发送图像，电容触摸通过独立 I²C 芯片读取。**第二路串口传用户操作产生的指令，不传屏幕像素，也不是连接普通 RGB 屏本体。**

帧缓冲大小：`宽 × 高 × 每像素字节数 × 缓冲数量`。800×480、RGB565 时，一帧 768000 字节，双缓冲 1536000 字节，通常需要外部 SDRAM。不能在 F429 内部 SRAM 或 CCM 中盲目分配这种大小的缓冲区。

如果项目已有 GUI 库、LTDC 初始化或触摸驱动，优先复用。没有时先做简单固定界面，不强制加入大型 GUI 框架或 RTOS。未确定屏幕参数前可实现与显示驱动解耦的 UI 事件和状态层。

### 第一阶段界面

| 控件 | 操作 | 对应请求 |
|---|---|---|
| 音色选择 | 风琴类／拨弦类 | SET_TIMBRE |
| 总音量滑条 | 0～100% | SET_MASTER_GAIN，换算到 0～1000 |
| 八个键位编辑入口 | 选压力键，再选音符 | SET_KEY_NOTE，目标为 1～8 |
| 静音开关 | 设置明确的开／关状态 | SET_MUTE |
| 停止当前发声按钮 | 使当前声音释音 | RELEASE_ALL |
| 八条输入压力条 | 显示 MCU 采集值 | 本地显示，无需向 FPGA 发显示指令 |
| 连接与应用状态 | 在线、超时、待应用、失败 | 根据状态机显示 |

### 第二阶段界面

- 八度 −／＋／复位：设置全局移调绝对值，范围 −24～+24 半音。
- 单音／和弦模式：SET_MODE。
- 各键和弦编辑：SET_CHORD。
- ADSR 参数：SET_ADSR_PARAM。

界面刷新建议 20～30 Hz，压力采集仍保持 1 kHz。音量滑动限速到约每 20 ms 一次，抬手发送最终值。触摸读取遵循控制器报告节奏；支持时可用 400 kHz I²C 和 INT 通知。

未实现的功能应隐藏或明确禁用。屏幕不能在 FPGA 返回“不支持”时仍显示该设置已成功生效。第一版不加入歌曲下载、录音、蓝牙或其他与当前目标无关的功能。

## 10. 建议的软件模块与工程集成方式

可按现有工程调整文件名，但建议保留清楚的职责边界：

| 模块 | 职责 |
|---|---|
| `pressure_acq` | ADC DMA 半区处理、八路快照、采集序号 |
| `pressure_link` | 压力帧打包、发送缓冲管理、DMA 发送和丢帧统计 |
| `protocol_crc` | 共用 CRC16 算法 |
| `control_protocol` | 控制帧序列化、流式解析、字段校验 |
| `control_client` | 请求队列、序号、ACK 匹配、超时和重试 |
| `instrument_settings` | 期望设置、已确认设置、范围验证和同步流程 |
| `ui_actions` | 将按钮和滑条操作映射为设置请求 |
| `board_display` / `board_touch` | 对接真实 LTDC、SDRAM、触摸芯片 |
| `app` | 启动顺序、周期服务、状态统计 |

要求：

- 延续项目使用的 HAL 和工程风格，不手动破坏 CubeMX 可重新生成的区域。
- 正确合并 ADC、UART、DMA 回调，不能为不同模块重复定义同一个 HAL 回调。
- 初版避免运行期动态分配；使用有界缓冲区和明确内存归属。
- ISR 与主循环／任务之间有明确并发保护；`volatile` 本身不能替代原子快照和缓冲所有权管理。
- 若采用 RTOS，沿用项目优先级及中断约束；无现有需求时无需引入 RTOS。
- 发生 DMA 或外设启动错误时保留可诊断状态，不伪装成正常运行。
- 不要用 PC 上跑通协议测试来冒充目标固件编译或板级时序验证。

## 11. FPGA 对接时必须保留的行为

此轮重点是 MCU 固件；除非用户继续要求，不需要把整套 FPGA 音频 RTL 一并实现。提供对接说明即可，但 MCU 行为要与以下约定一致：

- 压力串口接收器和控制串口接收器独立工作，控制链路另有回复发送器。
- 合法压力帧整组提交；参数配置在合适的音频采样边界提交。
- 跨时钟域的多位总线使用握手或异步 FIFO，不逐位随意同步。
- 压力链路超过 20 ms 无合法帧时，FPGA 使活跃声部释音并记录故障。
- 故障恢复后，各键先经历有效松开状态再允许重新触发。
- 控制链路失联时保留最后确认的设置；只要压力链路正常，就可继续演奏。
- 当前声部记录触发时的音符、音色及按键事件归属。改键位后，松开原按键仍要释放原事件对应声部。
- 同一键再次按下是新事件，不应把新压力重新施加到此前正在释音的旧声部上。
- FPGA 上电建议：音色 0、单音模式、移调 0、音量 300/1000、静音开启、八键默认音符。
- 和弦初值可为每键一个默认音符，后续由 MCU 配置为四音；不能声称仅因指令支持四音就已实现 32 复音。

## 12. 开发顺序和必须交付的结果

### 第一阶段：协议与压力采集

1. 检查已有工程，确认可确定的板级设置，列出缺失资料。
2. 实现 CRC、固定帧编解码和与硬件无关的必要测试。
3. 配置 TIM2 → ADC 扫描 → DMA 双半区 → 压力串口 DMA。
4. 给出引脚／Rank 表、CubeMX 设置和实际时钟计算。
5. 能以 1000 帧/秒发送完整八路数据，并记录异常。

### 第二阶段：控制与屏幕

1. 实现第二路串口接收解析、请求状态机、ACK、超时和重试。
2. 先打通 PING、音色、音量、键位、静音及状态查询。
3. 在真实屏幕资料完整后接入 LTDC、触摸与基础界面。
4. 实现界面待应用／成功／失败状态及配置同步。
5. 最后添加可选的和弦、八度、ADSR 功能。

### 测试和验收

| 验收项 | 判据 |
|---|---|
| CRC 与数据包 | 与本文全部向量一致，压力 22 字节、控制 16 字节 |
| 接收解析 | 正确处理分段、连续帧、负载含帧头、垃圾字节及坏 CRC |
| ACK 与重试 | 匹配事务；迟到回复不误更新；重试次数有界 |
| ADC 通道对应 | 只按某键时，对应 Rank 和压力帧字段正确变化 |
| 采集与发送 | 每路 1 kHz；正常序号连续；无混合快照或发送中覆盖 |
| 高界面负载 | 持续刷屏和操作滑条时，压力链路仍稳定 |
| 错误恢复 | 控制失联不拖死压力路径；队列不无限增长 |
| 参数边界 | 移调越界、无效音符、错误目标能被拒绝 |
| 真实板级验证 | 明确记录实际烧录、波形测量及仍未验证的项目 |

不需要为了简单 UI 文案写大量测试。重点测试协议、状态机和并发缓冲等容易引入实际故障的部分。

最终交付：源代码或实际工程补丁、CubeMX 与引脚配置说明、协议说明、编译／运行步骤、验证结果，以及尚未解决的硬件依赖。若只有可移植模块，明确标注其与完整可烧录工程的差别。

不要提前宣称整机延迟达到 ≤5 ms 或“无抖动”。1 kHz 压力采集本身就存在动作等待下一次采样的相位差；总延迟还包括模拟电路、滤波、传输、FPGA 和 DAC，必须实测。

# 给下一个 AI：FPGA 十二键触摸钢琴扩展（历史版本）

> 本文描述屏幕触摸键盘与 `AA55/AA56` 随页面切换的旧方案。当前 MCU 已改为 PCA9555 实体按键 + 12 路 ADC，并始终发送 `AA56`。实现 FPGA 接收端前请改读 [十二键实体钢琴接线与验收](十二键实体钢琴接线与验收.md)。

版本：2026-10-15。适用于当前 STM32F429BIT6 + FPGA 电子乐器工程。

**请直接在现有 FPGA 工程中实现并验证，不要另改 MCU 帧格式。先保留原来的 `AA 55` 八路 ADC 接收，再增加 `AA 56` 十二键触摸钢琴接收；两种输入共用 PB10 的 1 Mbps 串口，但任一时刻只使用一种。**

本文中的“必须”是 MCU 与 FPGA 的接口约定；RTL 模块怎么拆分可以按现有工程风格调整。

## 1. 本次 MCU 已经做了什么

- 屏幕第一页继续显示八路 ADC 压力，USART3 发送原 `AA 55`、22 字节压力帧。
- 第二页显示 C 到 B 的一个完整十二平均律八度：7 个白键和 5 个黑键。
- 黑键只有 C#、D#、F#、G#、A#；E-F 和 B-C 之间没有黑键。左右边界不补相邻八度的黑键，这是有意的边界处理。
- 第二页每 10 ms 发送一份 `AA 56`、34 字节完整键盘快照，约 100 帧/秒。
- 页面切换到第二页后，ADC 仍在 MCU 内采样，但 `AA 55` 帧暂停发送；返回第一页才恢复发送。
- 触摸按下稳定 20 ms 后生效，松开稳定 30 ms 后释放。
- `force` 表示本次 note-on velocity。同一次触摸确认时固定为 2048，按住期间保持不变，稳定松开后清零。
- MCU 已读取 GT9xx 的 `track_id` 和原始 `point size`，但当前没有实机校准数据，因此没有把接触面积直接换算成力度。以后可在 20..40 ms 触发窗口内标定轻触/重触映射。
- GT9xx 最多报告 5 个触点，所以画面有 12 键，但最多同时可靠按下 5 键。
- `Oct -` / `Oct +` 同时降低或升高全部 12 键一个八度，范围 C2-B2 到 C7-B7，默认 C4-B4。
- USART1 的 115200 控制链路不变，仍负责音色、总增益、静音、Release、状态查询和 ACK。

## 2. 接线和串口

| 信号 | MCU 引脚 | FPGA 方向 | 参数 |
|---|---|---|---|
| PRESSURE_OR_PIANO_RX | PB10 / USART3_TX | 输入 | 1,000,000 baud，8N1 |
| CTRL_RX | PB6 / USART1_TX | 输入 | 115,200 baud，8N1 |
| CTRL_TX | PB7 / USART1_RX | 输出 | 115,200 baud，8N1 |
| GND | MCU GND | 共地 | 必须连接 |

PB11 虽配置为 USART3_RX，但当前高速数据链路不要求 FPGA 回 ACK。不要在 PB10 数据流中插入 ASCII、调试字符或换行。

USART3 在线发送时间：

- `AA 55`：22 字节 × 10 bit / 1 Mbps = 220 us，正常约每 1 ms 一帧。
- `AA 56`：34 字节 × 10 bit / 1 Mbps = 340 us，正常约每 10 ms 一帧。

## 3. 原 ADC 帧保持不变

`AA 55 | seq LE16 | pressure[0..7] LE16 | CRC LE16`

总长 22 字节。CRC 覆盖字节 2 到 19。八个压力值均为 0..4095，高四位必须为 0。详细控制协议和原始压力要求继续参考 `给下一个AI_FPGA接收与控制开发清单.md`。

## 4. 新十二键帧

### 4.1 固定 34 字节格式

| 字节位置 | 长度 | 内容 |
|---|---:|---|
| 0..1 | 2 | 帧头 `AA 56` |
| 2 | 1 | 协议版本，固定 `01` |
| 3 | 1 | `base_note`，最低键 C 的 MIDI 音高编号 |
| 4..5 | 2 | `sequence`，小端 uint16，每帧递增并允许回绕 |
| 6..7 | 2 | `pressed_mask`，小端；bit0..bit11 对应 12 个半音 |
| 8..31 | 24 | `force[0]..force[11]`，每项小端 uint16 |
| 32..33 | 2 | CRC16，小端 |

CRC **只覆盖字节 2..31，共 30 字节**。

CRC 参数：CRC-16/CCITT-FALSE，poly=`0x1021`，init=`0xFFFF`，不反射，xorout=`0x0000`；字符串 `123456789` 的结果必须为 `0x29B1`。

### 4.2 键位含义

`midi_note = base_note + key_index`

| key_index / mask bit | 音名 |
|---:|---|
| 0 | C |
| 1 | C# |
| 2 | D |
| 3 | D# |
| 4 | E |
| 5 | F |
| 6 | F# |
| 7 | G |
| 8 | G# |
| 9 | A |
| 10 | A# |
| 11 | B |

默认 `base_note=60`，即 C4-B4。八度按钮只改变 `base_note`，所以不需要在串口里发送 12 个浮点频率。FPGA 可用 MIDI 编号查表得到 DDS 相位增量，或用

`frequency = 440 * 2^((midi_note - 69) / 12)`

离线生成查找表。运行时不要在 RTL 中实现浮点指数运算。

### 4.3 接收合法性

只有同时满足以下条件才提交整帧：

- 帧头、长度和 CRC 正确。
- 版本等于 1。
- `base_note <= 116`，保证最高的 `base_note + 11` 不超过 127。当前 MCU 实际只发 36、48、60、72、84、96。
- `pressed_mask[15:12]` 全为 0。
- 每个 `force[i] <= 4095`。
- mask bit 为 0 时，对应 `force[i]` 必须为 0。
- 建议进一步要求 mask bit 为 1 时 `force[i]` 非 0；当前 MCU 一定满足。

先在影子寄存器中收满和校验，再在同一个时钟边沿整体更新 12 路状态。CRC 错、字段错或半帧绝不能局部改变正在演奏的状态。

### 4.4 已验证测试向量

下面是完整 34 字节原始二进制的十六进制表示：

```text
AA 56 01 3C 34 12 07 0C
80 01 56 00 AA 0A 00 00
00 00 00 00 00 00 00 00
00 00 00 00 0A 00 FF 0F
6E 93
```

解释：版本 1，`base_note=60`，`sequence=0x1234`，mask=`0x0C07`。有效力度为 key0=384、key1=0x0056、key2=0x0AAA、key10=10、key11=4095，其余为 0。输入数组里即使给未按下键填了值，MCU 编码器也会清零。CRC 是 `0x936E`，线上按小端发送 `6E 93`。

## 5. 状态机和发声边沿

`AA 56` 是完整状态快照，不是每帧都重新触发的 Note On 事件。`force` 是按下边沿的 velocity，在同一次按住期间不变。

- 前一有效快照为 0、当前为非 0：触发一次 Note On。
- 前一有效快照为非 0、当前仍非 0：保持当前声部，不要重新触发包络；FPGA 可继续使用在 note-on 边沿锁存的 velocity。
- 前一有效快照为非 0、当前为 0：触发 Note Off / Release。
- 同一键按住期间 force 必须保持首次确认值。只有稳定松开后再次按下，才产生新的 velocity。
- `base_note` 改变时，建议原子释放旧音高，并按当前 mask 在新八度重新触发，避免同一 key index 留住旧音高。

当前 MCU 使用固定 velocity 2048，这是没有 point-size 标定数据时的保守方案。GT9xx `point size` 只是接触面积/电容响应的代理量，不是真实压力；完成不同手指、不同屏幕区域的轻触/重触采样后，才能把触发窗口内的 size 变化映射到 384..4095。

## 6. 两类帧共用一个 RX

推荐一个 UART 字节接收器，后接一个可识别两种帧头/长度的解析器：

1. 搜索 `AA`。
2. 下一字节为 `55` 时收满 22 字节；为 `56` 时收满 34 字节。
3. 候选帧内部即使再次出现 `AA 55` 或 `AA 56`，也不能提前重启，因为负载允许出现这些字节。
4. 收满后校验 CRC 和字段；失败时从候选数据的下一个字节继续滑动找帧头。
5. 成功时一次性提交，并按帧类型决定当前输入源。

MCU 切页时，正在 DMA 发送的旧类型完整帧可能先发送完，随后才出现新类型。FPGA **只在收到第一份完整、合法的新类型帧后切换输入源**。切换必须原子执行：释放旧来源的全部活跃声部、清旧边沿状态，再提交新快照。不要一看见第二个帧头字节就切模式。

模式切换建议：

| 收到的合法帧 | 当前模式 | 行为 |
|---|---|---|
| AA55 | ADC | 更新八路压力 |
| AA56 | PIANO | 更新十二键快照 |
| AA55 | PIANO | 先释放十二键声部，再切到 ADC 并提交 |
| AA56 | ADC | 先释放八路声部，再切到 PIANO 并提交 |

超时保护建议：ADC 模式连续 20 ms 没有合法 `AA 55` 就释放；钢琴模式连续 50..100 ms 没有合法 `AA 56` 就释放。超时恢复后的第一帧按全部键原先已松开处理，避免粘键。

## 7. 与现有音频接口衔接

建议解析器输出以下原子接口，具体命名可适配现有工程：

```text
input_mode             0=ADC, 1=PIANO
snapshot_valid         单周期脉冲
sequence[15:0]
piano_base_note[7:0]
piano_pressed[11:0]
piano_force[0..11][11:0]
source_changed         单周期脉冲
source_timeout         状态/脉冲
```

音频层应保存每个 key index 当前是否活跃及其实际 MIDI note。`Release` 控制命令仍从 USART1 到来，它应让当前两种来源的全部活跃声部进入释音。`Mute` 和总增益同样作用于两种来源。

## 8. 屏幕上哪些状态能证明什么

第二页显示：

- `mask` 和每个键底部的小力度条：证明 GT9xx 触摸和消抖在工作；当前按下键固定显示 velocity 2048。界面只以 10 Hz 局部更新，串口快照仍为 100 Hz。
- `AA56 seq`：是 MCU 准备的钢琴帧序号。
- `local-TC`：是 STM32 USART3 的本地发送完成次数。
- `drop`：是 MCU 发送队列覆盖或故障造成的丢帧计数。
- `control READY/APPLIED`：证明 USART1 请求和 FPGA 回包已完成。

**`local-TC` 增长不能证明 FPGA 已经收到或通过 CRC。** USART3 当前没有 ACK，因此仅看屏幕不能证明高速链路端到端正确。请按以下顺序验收：

1. RTL testbench 喂入本文向量、分段输入、连续帧、坏 CRC、负载内嵌帧头、模式切换和超时，检查原子提交与释放。
2. 逻辑分析仪接 PB10 和共地，以 1 Mbps/8N1 抓原始二进制；第二页应约每 10 ms 一份 34 字节帧，第一页约每 1 ms 一份 22 字节帧。可运行 `python tools/check_pressure_capture.py capture.bin --expect piano --seconds 10` 检查第二页抓包。
3. 上板用 FPGA ILA/SignalTap 类工具观察 `frame_valid`、`sequence`、mask、force、CRC 错误计数和 source mode。
4. 最终以实际发声验证：按 C4 只触发 MIDI 60，按 C#4 触发 61，按住 3 秒不反复触发且 force 保持 2048，松手后释放；切页、改八度、拔线均不能粘音。

若确实需要屏幕直接显示 FPGA 的 USART3 收包计数，需要另行扩展 USART1 诊断回复协议并同时改 MCU 和 FPGA；当前协议没有这个字段，不要把本地计数冒充 FPGA 回读。

## 9. FPGA testbench 必做项

- [ ] 单独验证 1 Mbps UART RX 的起始位、数据位顺序、停止位和允许的波特率误差。
- [ ] 合法 `AA 55` 以及合法 `AA 56` 各至少一个精确向量。
- [ ] 任意字节切分、两帧紧邻、前导垃圾、重复 `AA`。
- [ ] payload 内出现 `AA 55`、`AA 56` 时仍完整解析当前候选帧。
- [ ] CRC 高/低字节交换、单 bit 损坏、截断帧均不提交。
- [ ] 版本、base note、mask 高位、force 高位和 mask/force 不一致均按选定规则处理。
- [ ] sequence 从 FFFF 回绕到 0000；跳号只记诊断，不把后续合法帧丢掉。
- [ ] 0→按下只触发一次并锁存 velocity，按住期间 force 不变且不重复触发，按下→0 正确释放。
- [ ] base note 改变时没有旧音高残留。
- [ ] `AA55 -> AA56 -> AA55` 切换时每次都释放旧来源，没有粘音。
- [ ] ADC 20 ms、钢琴 50..100 ms 看门狗超时释放，恢复首帧能重新触发。
- [ ] USART1 Release/Mute/增益对两种来源都有效，控制 ACK 去重逻辑保持原行为。

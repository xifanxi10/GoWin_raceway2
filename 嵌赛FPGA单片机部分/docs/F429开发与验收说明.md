# F429 开发与验收说明（历史版本）

> 本文记录 2026-10-15 的“八路 ADC + 屏幕触摸钢琴”版本，已被 2026-10-25 的十二键实体钢琴实现取代。当前接线、数据流和验收请以 [十二键实体钢琴接线与验收](十二键实体钢琴接线与验收.md) 为准，不要再按本文的切页协议实施 FPGA 接收端。

更新日期：2026-10-15。工程：STM32F429BIT6，LQFP208，Cube FW F4 V1.28.3 / Keil ARMClang 6.22，无 RTOS。

已完成现有工程集成、八路 ADC 第一页、十二键触摸钢琴第二页、PC 原生 C 测试和目标工程编译。**尚未烧录本次固件，也没有实测新页面帧率、触摸操作或整机延迟。** 用户确认原工程屏幕此前正常显示和触摸，所以保留原屏幕时序、分辨率、GT9xx 和引脚方案。

`.ioc` 已同步定时器、采样时间、DMA 优先级、IRQ、层像素格式等修改。重新生成后保留 USER CODE 与 Instrument 分组；检查新增源文件仍参与编译、IRQ 仅定义一次、IRAM2 仍未用于 DMA 数据。此次没有运行 CubeMX 重新生成验证。

## 3. 时钟计算

已有配置：HSE=25 MHz，PLLM=25，PLLN=360，PLLP=2，SYSCLK/HCLK=180 MHz。

- APB1=45 MHz，因为 APB1 分频不为 1，TIM3CLK=90 MHz（现有默认 TIMPRE）。
- TIM3：90,000,000 / (89+1) / (999+1) = **1000 Hz**。
- APB2=90 MHz，ADC /4，ADCCLK=22.5 MHz。
- 每轮扫描约 8 × (144+12) / 22.5 MHz = **55.5 μs**，明显小于 1 ms。
- USART3：1,000,000 baud、8N1；第一页 22 字节约 **220 μs**、约 1 kHz，第二页 34 字节约 **340 μs**、约 100 Hz；两种帧不会同时发送。
- USART1：115,200 baud、8N1；16 字节约 **1.39 ms**。
- 原屏幕 PLLSAI：25 MHz /25 ×198 /3 /2 = **33 MHz**，总行列 1081×543，理论刷新约 **56.2 Hz**。
- 触摸仍以 10 ms 周期查询。第一页 ADC 柱形每 40 ms 更新、数字每 80 ms 更新；第二页琴键每 100 ms 更新；串口诊断每 1000 ms 更新。两页都只补画变化区域，琴键主体和 ADC 面板只在进入页面时完整绘制，避免单缓冲 LTDC 显示 DMA2D 擦除过程。压力采集和 USART3 发送周期不受界面刷新率影响。

144 cycles 是基于现有工程的初值，是否足够仍取决于传感器和模拟源阻抗。不能把 ADC 单轮 55.5 μs 当作整机演奏延迟。

## 5. 模块与运行行为

| 文件 | 用途 |
|---|---|
| protocol_crc / instrument_protocol | CCITT-FALSE CRC，压力/触摸钢琴/控制帧编码、控制流式解析、请求字段校验 |
| pressure_acq | 16 个 uint16 DMA 缓冲，HT/TC 分别取前/后八路；复制快照、序号和错误统计 |
| pressure_link | 22/34 字节共享 UART TX 双缓冲；按页面只接受一种来源，拥塞覆盖待发旧帧并计数 |
| control_client | 一个在途事务、8 条有界队列、ACK 匹配、20 ms 超时、最多 2 次重试、BUSY 退避 |
| control_transport | USART1 128 字节循环 DMA + HT/TC/IDLE，搬入 1024 字节软件接收环；主循环解析；统一 UART 回调 |
| instrument_settings | 用户期望与已确认配置、静音同步流程、在线状态、失败状态和查询 |
| touch_piano | 十二键按下/释放消抖、固定 note-on velocity、按住期间冻结力度、八度范围 |
| instrument_ui | 第一页八路 ADC，第二页 7 白 5 黑触摸琴键；不使用旧六页演示 UI |

第一页的压力帧在 ADC 回调中打包/启动非阻塞 TX DMA，**不等待主循环**，所以触摸 I²C 或绘制期间仍可继续发送。第二页继续本地采样 ADC，但链路拒绝 ADC 帧，由主循环每 10 ms 提交一份十二键完整快照。回调不绘图、不打印、不延时。UI 只取最新的完整快照，显示跳过中间采样属于正常行为，不计为链路丢帧。

TX DMA 使用自己的固定存储，ADC/界面不能改写正在发送的数据。临界区保存并恢复 PRIMASK，不无条件开中断。采集序号从 1 开始，按 65536 回绕；拥塞时 FPGA 能看到序号跳变。

控制超时从 UART **TC 完成回调时间戳**开始计时；重试沿用相同序号和内容，总共最多发 3 次。CRC 错误、错误事务序号、目标或原命令均不能提交配置；BUSY 退避 5 ms。真正的 UART 发送超时另有 100 ms 看门狗，不混同为 ACK 超时。

USART1 RX 回调读取实时 NDTR，避免 IDLE 与迟到 HT 通知重复搬运数据。接收环满会计数、丢弃不完整流、重启控制接收并报告事务失败。主循环里的串口恢复不影响硬件定时压力路径。

压力串口错误会在主循环中 abort/recover；ADC OVR/DMA 错误则记录计数并停止定时采集，屏幕显示 ADC FAULT，避免把失去完整性的扫描伪装成正常数据；此版本排查后复位恢复 ADC，不自动重建扫描。

## 6. 初次连接与界面

上电顺序：准备 DMA/ADC/UART → 启动 TIM3 采集 → 开始控制链路并发送静音 → 初始化界面 → 主循环服务。

同步共 22 个事务，每个都必须成功后才推进：

1. 静音开启。
2. 移调清零。
3. 音色。
4. 八个键的音符。
5. 八个键的单音和弦初值（一个默认音符，剩余槽 FF）。
6. 目标移调、单音模式、总音量。

默认八键 `[60,62,64,65,67,69,71,72]`，音量 300/1000、音色 0、静音。同步完成后仍保持静音；采集已运行且已有样本，用户点击 Mute toggle 才请求解除静音。初始化必须由 FPGA 支持表中同步命令；若回复“不支持”，界面显示失败，不跳过并谎称同步成功。

界面英文标签用于复用现有 ASCII 字库，含义如下：

| 控件 / 状态 | 含义 |
|---|---|
| Organ / Pluck | 风琴类 / 拨弦类音色 |
| Gain | 拖动总音量，约每 20 ms 提交最新值，抬手再提交最终值 |
| K1～K8 压力条 | 触摸选择编辑键；显示本地 0～4095 原始压力 |
| Note - / Note + | 修改所选键音高，0～127；这里的 MIDI 编号只表示音高，不是 MIDI 协议 |
| Mute toggle | 请求明确的开/关静音值 |
| Release | 所有活跃声部进入释音 |
| Resync | 当前队列空闲时请求重新静音同步，忙时显示请求拒绝 |
| Want / FPGA、数值 a/b | 期望值 / 已确认值；`?` 表示完整配置尚未确认 |
| SYNC / MUTED | 正在静音同步 |
| PENDING | 请求等待处理或确认 |
| APPLIED | 当前期望配置已确认 |
| UNAPPLIED / FAILED | 尚有未应用配置 / FPGA 拒绝或事务失败 |
| OFFLINE / NEEDS SYNC | 控制无回复 / 尚未同步 |
| REQUEST REJECTED | 本地范围检查、未同步、队列满或操作条件不满足；不静默丢掉关键按钮 |
| Piano > / < ADC | 在八路压力页与十二键触摸钢琴页之间切换，同时切换 USART3 帧类型 |
| Oct - / Oct + | 全部 12 键一起降/升一个八度，范围 C2-B2 到 C7-B7 |
| mask / 琴键底部力度条 | 本地触摸稳定状态及 note-on velocity，最多五点同时触摸；当前固定为 2048 并在按住期间保持不变 |
| AA56 seq / local-TC / drop | 钢琴帧序号 / MCU 本地发送完成数 / 本地丢帧数；不能单独证明 FPGA 已解析 |

界面暂不暴露和弦编辑、模式编辑及 ADSR 编辑。当前和弦配置为单音初值，不意味着已实现 FPGA 32 复音。钢琴页的八度直接编码为新快照的 `base_note`，不使用 USART1 移调命令。

空闲时每秒 GET_STATUS；断线后以 PING 探测，重新连通后再静音同步。观察到全局状态不一致也触发同步。协议没有启动会话号，因此**不能无条件识别 FPGA 所有瞬时复位**；GET_STATUS 也不能读回完整键位或 ADSR。

## 7. FPGA 接口约定

第一页 ADC 帧固定 22 字节：`AA 55 | seq LE16 | key1..8 LE16 | CRC LE16`，CRC 覆盖 2～19，高四位清零。

第二页钢琴帧固定 34 字节：`AA 56 | version=01 | base_note | seq LE16 | mask LE16 | force[12] LE16 | CRC LE16`，CRC 覆盖 2～31。mask bit0..11 对应 C、C#、D、D#、E、F、F#、G、G#、A、A#、B。两种帧共用 PB10，均无需逐帧 ACK；FPGA 收到第一份完整合法的新类型帧后，必须释放旧来源并原子切换。

控制帧固定 16 字节：`5A A5 | 01 | cmd | seq LE16 | target | 00 | P0..P5 | CRC LE16`，CRC 覆盖 2～13。普通 ACK=0x80，P0 原请求命令、P1 状态，其余 0。GET_STATUS 成功只回 0x81。

CRC：CCITT-FALSE，poly=1021，init=FFFF，不反射，xorout=0000，`123456789 → 29B1`。

FPGA 必须对合法整帧原子更新压力，坏帧不提交；参数仅成功提交后 ACK。重发完全相同的请求只重发缓存的回复，不重复执行。压力超过 20 ms 没有合法帧时主动释音，恢复后先松开再触发。MCU 不生成音频、波形或 ADSR 音频包络。

完整命令码与字段以同目录 [原始交接文档](原始交接文档_F429电子乐器固件.md)、[FPGA 十二键扩展](给下一个AI_FPGA十二键触摸钢琴扩展.md) 及 `instrument_protocol.h/.c` 为准。本次增加了 `AA 56` 线格式，但未实现或验证 FPGA RTL。

## 8. 已执行验证

`python tools/run_tests.py` 调用本机 GCC 编译**实际生产 C 源码**：

- CRC 文档向量、22/34/16 字节编码、小端顺序和未按下键力度清零。
- 控制分段/连续帧、垃圾、重复头、负载含头、坏 CRC、截断候选重同步。
- 参数/目标/保留字段、音符/移调/音量/和弦/ADSR 范围。
- 真实 TC 之后开始 ACK 超时，最多两次重试，同序号同内容，BUSY 退避。
- 错误 ACK、迟到 ACK、错误目标/命令、状态回复、队列满和未发送参数合并。
- ADC 两半区对应、发送中存储不被覆盖、只保留最新待发帧、PRIMASK 恢复、65536 序号回绕。
- 模拟 DMA 环绕、IDLE/HT/TC、迟到重复通知、接收环满后的恢复。
- 22 步静音同步、期望/确认值分离、失败保留原确认值、重连、状态不一致。
- 22/34 字节 DMA 所有权、来源切换、旧待发帧清除、钢琴按下/释放消抖、按住 3 秒力度冻结、五点状态和 tick 回绕。

HAL 替身测试只证明软件状态与缓冲行为，不代表测量了真实 DMA 延迟或波形。Keil 目标固件另行编译，两者区别明确。

## 9. 上板验收顺序

1. Keil 打开工程，Rebuild，确认没有错误；先将开关置 0 测压力和控制，再置 1 联调屏幕。下载的是当前新生成 HEX，不要误用旧固件。
2. 连接逻辑分析仪/支持 1 Mbps 的 TTL 串口接收器到 PB10，共地，按二进制接收；第一页应为 `AA 55` 22 字节约 1 kHz，第二页应为 `AA 56` 34 字节约 100 Hz，CRC 正确、seq 连续（FFFF→0000 正常）。
3. 固定观察 10 秒应约 10000 帧；同时在 Keil Watch 看 `pressure_samples` 的每秒差值约 1000。先检查 TIM3 PSC=89/ARR=999 和 ADC DMA NDTR 在 16→0 循环。
4. 分别改变 PA0～PA7 输入，只对应 Rank/帧字段变化；不要拿悬空模拟输入当作压力稳定性结果。
5. 捕获文件须为原始二进制，不是带时间戳的文本。第一页运行 `python tools/check_pressure_capture.py capture.bin --expect adc --seconds 10`，第二页改用 `--expect piano`；混合切页抓包可保留默认 `--expect auto`。工具检查两种帧的 CRC、字段、序号、切换和帧率。抓包边界的少量首尾碎片可正常出现；大间隙、复位或乱序的序号计数按模 65536 解释。
6. FPGA 控制端按交接协议接 PB6/PB7；先确认静音同步逐条 ACK，成功后操作音色、音量、键位和解除静音。用错误 CRC、不匹配序号、状态 4/6、不给 ACK 等注入，检查不误报成功、重试最多 2 次。
7. 开启屏幕，持续拖动音量和修改键位，检查压力序号/帧率，观察 DMA/OVR/drop 错误计数；切到钢琴页逐一按 12 键、长按、五点按压、换八度、返回 ADC 页，确认帧类型切换且没有粘音。不要把 `local-TC` 或 PC 单元测试当作 FPGA 收包通过。
8. 断开控制回复，确认压力输出继续；恢复回复后先静音同步，用户再解除静音。模拟压力故障时还需确认 FPGA 的 20 ms 失联释音逻辑。
9. 测量从传感器动作到 DAC 输出的整机延迟，再判断赛题要求；本次没有宣称 ≤5 ms 或 ≤10 ms 实测达标。
